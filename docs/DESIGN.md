## 1. 设计摘要

本产品是一个纯前端 PWA（渐进式网页应用），面向一名葡萄牙语专业大一学生的日常阅读与词汇学习。核心能力由五个页面构成：今日（打卡与进度）、阅读（课文精读与三种练习模式）、单词（词库管理）、复习（间隔重复闪卡）、统计（日历与设置）。

三个关键设计判断：

1. **发音以服务器预生成音频为主，系统语音为兜底。** 欧葡（pt-PT）与巴葡（pt-BR）在元音弱化与词尾 s 的读法上差异显著，跟读巴葡音频会与课堂方向相反。音频在 Mac mini 上用 Azure pt-PT 神经语音批量合成并推送 VPS，前端只负责播放；无网络或无音频时退回设备内置语音。
2. **跟读第一版只做对比，不做自动打分。** 语音识别模型的设计目标是尽量听懂，遇到口音会自动纠正为正确文字，因此分数无法反映发音地道与否，打分反而误导。改为「原音播放、录音、原音与我的录音连播对比、不满意重录」。
3. **数据先本地、后同步。** 首版数据只存设备本地（localStorage），配手动导出导入；多设备同步作为第二阶段，通过 VPS 上的轻量接口实现，不在首版引入账号体系。

## 2. 产品定位与边界

### 2.1 目标用户

| 维度 | 描述 |
|---|---|
| 身份 | 葡萄牙语专业大一学生（澳门大学，欧葡方向） |
| 设备 | iPhone 与 iPad，以 Safari 打开并添加到主屏幕为主 |
| 网络 | 校内 Wi-Fi 与家庭网络交替，移动网络为辅 |
| 使用时段 | 碎片时间，单次 5 至 15 分钟；晚间可能有一段较长阅读 |
| 动机 | 课程词汇量与听说能力需要日常累积，课堂内容需要反复巩固 |
| 障碍 | 不宜长时间盯着屏幕；需要即时、可见的进度反馈来维持节奏 |

### 2.2 核心价值

| 价值点 | 具体表现 |
|---|---|
| 降低坚持成本 | 连续打卡天数、进度条、待复习数量三个指标常驻首屏，让进度始终可见 |
| 提供真实欧葡输入 | 全部课文音频采用 Azure pt-PT 神经语音，口音与课堂一致 |
| 闭环覆盖读听说 | 阅读（输入）、跟读（输出）、听写（精确听辨）、词汇（记忆）四条路径互相补充 |
| 随时可用 | PWA 添加到主屏幕后离线可用，弱网环境下退回系统语音仍能继续学习 |
| 内容可迭代 | 课文与音频在 Mac mini 上批量生成并推送，联网打开即可看到新内容 |

### 2.3 明确不做（首版非目标）

| 非目标 | 原因与替代方案 |
|---|---|
| 上架 App Store | PWA 已能满足主屏启动、离线、全屏需求，省去签名、审核与年费 |
| 用户账号与社交 | 单用户自用工具，加入账号体系只会增加摩擦；进度查看由家长侧导出数据解决 |
| 自动发音打分 | 见 1.2 判断 2；改为对比模式 |
| 云端题库与教材同步 | 版权风险且教材版本不确定；课文全部原创 |
| 复杂后台管理系统 | 首版后台即「Mac mini 上的内容工厂」，采用文件与脚本交付，不需要管理界面 |
| 多语言界面 | 界面固定中文，葡语仅出现在学习内容中 |
| 复杂动画与游戏化 | 过度装饰会挤占内容空间，也增加维护成本 |

### 2.4 版本演进复盘

本产品经过四轮迭代，下表记录每一轮的实际变更与遗留问题，用于说明当前设计从何而来。

| 版本 | 主要变更 | 遗留问题 |
|---|---|---|
| v1 基础版 | 四页结构（今日、单词、复习、统计）；localStorage 单键存储；间隔 0/1/2/4/7/15/30 天；缓存优先 Service Worker | 无课文内容；发音依赖设备语音，欧葡质量不可控；数据仅本机、换设备即丢 |
| v2 内容版 | 新增「阅读」页与 8 篇原创课文；materials.json 外置；发音默认改 pt-PT；单词页支持批量导入；Service Worker 改联网优先 | 课文无音频；仍无跨设备同步；课文朗读为整段播放，无法逐句跟读 |
| v3 跟读版 | 音频按句与按生词预生成；新增逐句点读与当前句高亮；0.75 倍速；跟读录音与对比；听写模式与三色 diff；VPS 上增加发音代理 | 依赖 Azure 额度与代理服务尚未落地；录音仅存内存刷新即失；iOS 存储可能被系统回收 |
| v4 规划版 | 家长侧内容工厂流水线；音频质检（ASR 回读比对）；每日额度与限流；同步接口预留 | 仍为单文件脚本堆叠，缺乏模块边界与数据契约；无自动化测试与监控 |

## 3. 角色、使用场景与需求优先级

### 3.1 角色

| 角色 | 权限与关注点 | 使用设备 |
|---|---|---|
| 学生（使用者） | 完成打卡、读课文、跟读、听写、维护词库、复习 | iPhone / iPad |
| 家长（内容作者与管理） | 编写与推送课文、生成音频、查看学习概况、调整目标 | Mac mini（生产）、手机（查看） |
| 运维（隐形） | VPS 可用性、TLS 证书、额度守护 | Mac mini / 笔记本 |

### 3.2 关键场景

| 编号 | 场景 | 触发条件 | 期望路径 | 优先级 |
|---|---|---|---|---|
| S1 | 早读打卡 | 早晨起床后 | 打开今日页，看进度，记录阅读时长，打卡 | 高 |
| S2 | 精读一篇课文 | 课后 | 打开阅读页，逐句点读，看中文对照，读语法点，把生词批量加入词库 | 高 |
| S3 | 跟读练习 | 晚间 | 切到跟读模式，逐句听原音、录音、对比、重录 | 高 |
| S4 | 听写巩固 | 晚间 | 切到听写模式，听一句写一句，检查并看差异 | 中 |
| S5 | 复习词汇 | 每日固定时段 | 复习页清空当天队列，答错的重新排队 | 高 |
| S6 | 导入课本词表 | 每周 | 单词页批量粘贴导入，自动去重 | 中 |
| S7 | 查看坚持情况 | 每周 | 统计页看月历与累计数据 | 中 |
| S8 | 换设备或恢复 | 迁移前 | 统计页导出备份，新设备导入 | 中 |
| S9 | 家长了解进度 | 每周 | 读取学生导出的备份，或后续通过同步接口查看 | 中 |
| S10 | 内容更新 | 每周 | Mac mini 加课文，跑脚本，推送，学生联网即见 | 中 |

### 3.3 需求优先级排序

| 层级 | 需求 |
|---|---|
| P0（必须有） | 打卡与进度可见、课文阅读、逐句发音、单词本、间隔重复复习、数据本地存储与备份 |
| P1（应该有） | 跟读录音对比、听写模式、批量导入、每日目标可调、统计日历 |
| P2（可以有） | 多设备同步、家长进度查看、SM-2 算法、课文自动分句、音频离线预下载 |
| P3（暂不做） | 自动打分、社交、后台管理界面、云端题库 |

## 4. 信息架构与导航

### 4.1 底部标签栏（五个一级入口）

| 顺序 | 标签 | 职责 | 主要内容 |
|---|---|---|---|
| 1 | 今日 | 今日状态与快速记录 | 连续打卡天数、阅读与新词进度条、待复习数量、打卡按钮、其他阅读记录表单 |
| 2 | 阅读 | 课文消费与练习 | 课文列表、课文详情、阅读与跟读与听写三模式切换、生词卡、理解问题 |
| 3 | 单词 | 词库维护 | 添加单词、批量导入、搜索、发音、删除 |
| 4 | 复习 | 记忆巩固 | 闪卡、发音、记住了与没记住 |
| 5 | 统计 | 回顾与设置 | 月历、累计数据、发音与目标设置、备份导入导出 |

导航固定在底部，适配 iOS 安全区（`env(safe-area-inset-bottom)`），主内容区预留同等底部内边距，避免被标签栏遮挡。切换标签时若正在播放音频或录音，必须先停止。

### 4.2 页面内层级

| 层级 | 路径 | 返回方式 |
|---|---|---|
| L1 | 标签页 | 点击标签切换 |
| L2 | 课文详情 | 阅读页内返回按钮，回到课文列表并回到顶部 |
| L3 | 跟读与听写 | 课文详情内分段控件切换，不新增页面栈 |

原则：层级不超过两层，全部在单页内切换，避免 iOS 上手势返回造成状态错乱。

## 5. 功能规格（逐页）

### 5.1 今日页

**模块 A：状态卡**

| 字段 | 规则 |
|---|---|
| 日期 | 显示本地日期，格式 `YYYY-MM-DD` |
| 问候语 | 固定葡语问候（Olá! Bom estudo!），可作为每日固定的正反馈 |
| 连续打卡天数 | 当日已打卡则计入，否则从昨日开始向前连续计数，结果为 0 时显示 0 |

**模块 A2：下一步卡片（首屏第一屏，第一优先级）**

今日页顶部放一张卡片，只给一个明确的下一步动作，不给仪表盘。按状态判断，顺序固定：

| 状态 | 卡片文案 | 按钮 | 点击去向 |
|---|---|---|---|
| 有到期复习词 | 「今天有 N 个词要复习」 | 开始复习 | 复习页，直接进入第一轮 |
| 无到期词且有未读完课文 | 「继续读：课文标题」 | 继续阅读 | 阅读页打开该课文 |
| 两项都完成 | 「今天完成了，明天见」 | 打卡 | 触发打卡 |
| 有到期词但积压（>50） | 「先复习，不加新词」 | 开始复习 | 复习页，并在上方标注积压提示 |

设计理由：原设计首屏是四个进度条，展示的是「还差多少」，这是**差值的负反馈**。改为一句人话加一个按钮，把仪表盘变成导航。用户每晚打开 App 只需要点一次就能进入正事。

**模块 A3：周目标（连续天数的兜底）**

连续打卡天数旁边显示「本周 X/5」。每周一零点重置，X 为本周已打卡天数。达标天数可设置，默认 5。

设计理由：连续天数一旦断掉，容易让人想彻底放弃。周目标给了一个更宽容的达标口径，一周完成 5 天即算达标，偶尔断一天不会前功尽弃。这比做「补签卡」简单得多，代价只是统计逻辑，无额外界面。

**模块 B：今日任务卡**

| 指标 | 计算方式 | 目标来源 |
|---|---|---|
| 阅读分钟 | 当日记录列表的分钟数求和 | 设置中的每日阅读目标，**默认 15** |
| 新单词 | 当日新增单词计数 | 设置中的每日新词目标，**默认 5** |
| 复习次数 | 当日复习操作累计 | 无目标，仅展示 |
| 跟读句数 | 当日跟读录音完成次数累计 | 无目标，仅展示 |
| 听写句数 | 当日听写检查次数累计 | 无目标，仅展示 |
| 待复习数 | 到期单词数量（复习日不晚于今天） | 无目标，仅展示 |

打卡规则：阅读分钟与新词均达标时可直接打卡；未达标时弹出确认框，确认后仍可打卡（防止一天被卡死）。打卡后按钮变为已完成状态，且不重复计数。

**模块 C：其他阅读记录**

| 字段 | 校验 |
|---|---|
| 标题 | 非空 |
| 分钟数 | 正整数 |
| 笔记 | 可空，提示学生尝试用葡语写一句话 |

记录写入当日列表，即时刷新进度条。此处记录与课文详情内的「读完了，记录」共用同一份当日数据。

### 5.2 阅读页

**课文列表**

| 元素 | 说明 |
|---|---|
| 课文总数 | 顶部提示，例如「共 8 课」 |
| 离线音频下载 | 按钮，逐个拉取所有课文音频以填充缓存，结束后显示已下载计数 |
| 课文条目 | 难度标签、葡语标题、中文标题、预计分钟数、已读完标记 |

**课文详情**

| 模块 | 内容与交互 |
|---|---|
| 头部 | 返回、难度标签、标题、朗读全文按钮、停止按钮、显示或隐藏中文按钮 |
| 正文 | 按段落分组，每句为可点击单元；点击只朗读该句；当前朗读句高亮 |
| **逐句中文** | **长按某句显示该句的中文**，松开或再次长按隐藏。该课文有 `sents[].zh` 时启用 |
| 中文对照 | 整段显示，按原段落换行。`sents[].zh` 缺失时只提供整篇对照，不报错 |
| 语法点 | 中文讲解，来自内容作者 |
| 生词卡 | 每条含葡语、发音按钮、加入按钮、释义、例句；已加入的显示为已加入状态且不可重复加入 |
| 理解问题 | 折叠展示问题与参考答案，默认收起 |
| 完成记录 | 已读日期提示，分钟数输入（默认课文建议时长），记录按钮 |

**难度退路**

课文难度不可调（标签为 A1/A2），但提供三种降低门槛的手段：

| 手段 | 作用 |
|---|---|
| 0.75 倍速 | 已在功能三模式中。语速放慢，不改变音调 |
| **逐句中文** | 长按单句显示中文。不知道整句意思时可以只看一句，不必理解全篇 |
| 补 A1 课文 | 内容端控制。下一批课文多供应 A1 难度 |

原则：**卡住的损失大于慢下来的损失**。跳过的课文是永久放弃，慢下来只是多花几分钟。因此不设「跳过课文」，而是把门槛逐级降低。

**三种模式**

| 模式 | 目的 | 交互 |
|---|---|---|
| 阅读 | 输入理解 | 逐句点读、可显示中文、看语法点与生词 |
| 跟读 | 语音输出 | 单句展示，逐句播放原音，录音后可单独播放我的录音或原音接我的录音连播 |
| 听写 | 精确听辨 | 播放单句，输入框作答，检查后给出逐词差异与正确词数 |

模式切换时重置句内索引，清空听写作答与结果，停止播放与录音。

### 5.3 单词页

**添加单词**

| 字段 | 校验与说明 |
|---|---|
| 葡语 | 非空；关闭自动大写、自动纠错与拼写检查，避免葡语被系统改写 |
| 中文释义 | 非空 |
| 例句 | 可空 |

新增单词的默认复习日为当天，熟练度为 0，即当天即进入待复习队列。写入前做大小写不敏感去重，重复则拒绝并提示。

**批量导入**

| 项 | 说明 |
|---|---|
| 输入格式 | 每行一条，字段用竖线或制表符分隔，依次为葡语、释义、例句（可省略） |
| 解析规则 | 去除首尾空白，缺葡语或释义的行跳过 |
| 去重 | 与已有词库及本批内部去重 |
| 反馈 | 提示本次新增数量，重复的自动跳过 |

**词库列表**

| 元素 | 说明 |
|---|---|
| 搜索框 | 按葡语与中文释义做大小写不敏感包含匹配 |
| 词条 | 葡语、发音按钮、删除按钮、释义、例句、熟练度与下次复习日期 |
| 排序 | 按加入时间倒序，最新的在最上方 |
| **错词本筛选** | 顶部加一个筛选开关「总记不住的词」，条件为 `lapse >= 3`，按 `lapse` 从高到低排。这批词是复习优先级的真实来源 |
| 删除 | 二次确认后从词库移除，不影响历史统计 |

**`lapse` 与 `box` 的区别**：`box` 是当前熟练度（决定下次复习日期），`lapse` 是历史累计失败次数（只增不减）。点「没记住」会让 `box` 归零并使 `lapse` 加一，但**任何情况下都不重置 `lapse`**，否则错词本会永远漏掉这些词。

### 5.4 复习页

| 规则 | 说明 |
|---|---|
| 队列构建 | 取到期单词，随机打乱 |
| **每轮上限** | 每轮最多取 `set.revBatch`（默认 30）个。做完一轮后提示「再来一组 / 今天到此为止」，不想继续可直接停 |
| **积压判定** | 待复习超过 50 个时视为积压。积压期间今日页提示「今天先复习，不加新词」，且打卡条件从「新词达标」改为「完成一轮复习」 |
| **没记住的词当轮必现** | 点「没记住」会使 `box` 归零、`due` 设为今天，并放回队尾。它会在同一轮里反复出现直到点「记住了」。因此**只要队列里有没记住的词，队列不可能提前清空** |
| 到期不下线 | 熟练度 6 对应 30 天间隔，该词每 30 天仍会出现一次，**不会永久消失** |
| 卡片正面 | 葡语、发音按钮、提示「先回想意思，再点卡片查看」 |
| 卡片背面 | 中文释义与例句 |
| 判定 | 两个按钮：没记住、记住了 |
| 计分 | 每次判定计入当日复习次数 |
| 没记住 | 熟练度归零，复习日改为当天，重新排入当天队列尾部 |
| 记住了 | 熟练度加一（上限 6），复习日按间隔表顺延 |
| 完成态 | 队列清空后显示完成页与鼓励语 |

点击卡片任意处翻面；点击发音按钮不触发翻面（需阻止事件冒泡）。

### 5.5 统计与设置页

| 模块 | 内容 |
|---|---|
| 月历 | 按当月天数渲染，周日起始；深绿为已打卡，浅绿为当日有学习但未打卡 |
| 累计数据 | 打卡天数、已读课文数、单词总数、已掌握单词数（熟练度不低于 5）、累计阅读分钟 |
| 发音设置 | 备用发音语言选择（欧洲葡语或巴西葡语），仅在无音频文件时使用 |
| 目标设置 | 每日新词目标、每日阅读分钟目标、每轮复习上限、每周达标天数 |
| 数据管理 | 导出备份文件、导入备份文件（覆盖前二次确认） |

## 6. 学习算法设计

### 6.1 间隔重复表

| 熟练度 box | 对应间隔 | 含义 |
|---|---|---|
| 0 | 0 天 | 当天必须复习 |
| 1 | 1 天 | 初识 |
| 2 | 2 天 | 短期巩固 |
| 3 | 4 天 | 进入中短期记忆 |
| 4 | 7 天 | 一周后巩固 |
| 5 | 15 天 | 进入长期记忆 |
| 6 | 30 天 | 达到稳定掌握 |

上界为 30 天。统计口径：熟练度大于等于 5 计为「已掌握」，与统计页展示一致。

### 6.2 判定与调度

| 输入 | 处理 |
|---|---|
| 记住了 | box = min(box + 1, 6)；due = 今天 + 间隔表[box] |
| 没记住 | box = 0；due = 今天；重新入队，今日再练一次 |

### 6.3 听写判定算法

三步处理，目的是只惩罚真正听错的部分，不惩罚重音符号差异与标点。

| 步骤 | 处理 |
|---|---|
| 归一化 | 转小写，去除除字母数字空白与连字符以外的符号，按空白切分为词序列 |
| 比对 | 采用最长公共子序列动态规划，逐位置比较去重音后的词形 |
| 上色 | 完全一致为绿；去重音后一致但拼写不同（通常是重音符号）为橙；参考句中有而作答中缺失或不一致为红并加下划线 |

判定统计「写对词数 / 参考词数」。

**风险与取舍**：欧葡口语中元音弱化严重，弱读音节在文本中常被省略，逐词严格比对可能给出偏低分数。本设计已通过去重音与忽略标点降低误判，但首版仍需教师或家长抽样核对体验。若挫败感明显，可退化为「只标出漏写与明显错词」，不逐词上色。此项列入待决策项 D3。

### 6.4 算法演进方向

| 方案 | 收益 | 代价 |
|---|---|---|
| 维持固定间隔表 | 零成本，行为可预测 | 无法个性化，难度低与难度高的词用同一节奏 |
| 引入 SM-2 | 调度更精细，需记录难度与易度因子 | 实现与数据结构复杂度上升，参数需调优 |
| 引入 FSRS | 效果优于 SM-2 | 依赖特定库与更多历史数据，首版过重 |

首版采用固定间隔表，box 与复习日期字段已为后续算法升级预留空间（增加难度因子字段即可）。

## 7. 发音、跟读与听写设计

### 7.1 三层发音与降级链

| 优先级 | 来源 | 条件 | 说明 |
|---|---|---|---|
| 一级 | 预生成音频文件 | 课文音频存在，或代理返回 200 | Azure pt-PT 神经语音，音质与口音最接近课堂 |
| 二级 | VPS 发音代理即时合成 | 无预生成音频但网络可达 | 首次点击时合成并长期缓存到 VPS |
| 三级 | 设备内置系统语音 | 离线或代理失败 | 使用设置中指定的备用语言（建议欧洲葡语） |

降级必须静默完成，不能因播放失败打断学习流程。

### 7.2 音频资源策略

| 项 | 规则 |
|---|---|
| 粒度 | 课文按句切分，每个生词单独一条 |
| 格式 | MP3，单声道，24 kHz，48 kbps |
| 命名 | 声音标识与文本的散列值，取前 16 位十六进制，加 `.mp3` |
| 幂等 | 同一声音与同一文本只生成一次，改课文只重生成改动的句子 |
| 缓存（前端） | 音频内容不变，Service Worker 对音频路径采用缓存优先 |
| 缓存（服务端） | 代理按同一命名规则落盘，进程重启不失效 |
| 离线 | 阅读页提供「下载全部音频」按钮，逐条拉取填充浏览器缓存 |

### 7.3 跟读模式设计

| 步骤 | 交互 | 设计理由 |
|---|---|---|
| 1 听 | 播放原音，可重复 | 建立正确听觉记忆 |
| 2 说 | 点击录音，再次点击结束 | 一次录音即可对比，避免频繁授权 |
| 3 比 | 单独播放我的录音，或原音接我的连播（间隔约 300 毫秒） | 听觉对比优于文字对比 |
| 4 重录 | 不满意可覆盖重录，旧录音的临时地址被释放 | 不增加复杂度 |

| 约束 | 处理 |
|---|---|
| 单句录音 | 录音对象与句索引绑定，切换句时自动失效 |
| 离开页面 | 切标签或切课时自动停止录音 |
| 麦克风权限 | 首次使用弹出系统授权；未授权时给出明确指引（设置与 Safari 的麦克风开关位置） |
| 存储 | 录音为页面内存中的临时地址，刷新即失效（首版取舍，见风险 R6） |
| 播放音量 | 提示佩戴耳机，避免外放失真 |

### 7.4 录音与评分边界

第一版不做自动打分。语音识别模型的目标是尽量听懂，遇到口音会自动纠正为正确文字，因此其输出只能回答「有没有被听懂」，无法回答「发音是否地道」，更无法定位具体音素错误。基于此输出的分数会误导学习者，把「识别得分低」误解为「自己读错」。第一版只提供对比，听辨差异由学生本人与教师判断。

后续若上传录音到服务端，可做两件有参考价值的事：一是异步转写后提示哪些词没有被识别出来（此项对发音改进有实际意义）；二是供家长或教师抽样听评。识别与转写任务在 Mac mini 上排队执行，不放在 VPS 上执行。

## 8. 客户端数据模型

### 8.1 存储选型

| 方案 | 结论 |
|---|---|
| localStorage | 首版采用。同步读写、实现简单、导出即整个键值 |
| IndexedDB | 第二阶段考虑。录音与课文正文体积上升后需要 |
| 内存变量 | 音频二进制与录音对象在内存中，用临时地址引用，不入存储 |

**已知风险**：iOS 对 Web 存储有回收策略，长期未打开的 PWA 数据可能被系统清理，且清理后不通知。

**关键事实（决定缓解策略）**：iOS Safari 遵循「脚本存储超过 7 天未使用即清除」的规则，但**添加到主屏幕的 Web App 不受这条规则限制**。因此「始终在主屏 App 内使用」是降低 R1 风险最有效的一条措施，优先级高于任何提醒文案。首版通过导出备份的人工习惯与家长抽查缓解，根治需改为 IndexedDB 并引入备份时效提醒。

### 8.2 数据结构（键：单一顶层键，值为一个 JSON 文档）

| 字段 | 类型 | 说明 |
|---|---|---|
| words | 数组 | 单词条目 |
| words[].id | 数 | 单调递增唯一标识 |
| words[].pt | 文本 | 葡语词或词组 |
| words[].zh | 文本 | 中文释义 |
| words[].ex | 文本 | 例句，可空 |
| words[].a | 文本 | 预生成音频相对路径，可空 |
| words[].box | 数 | 熟练度 0 至 6 |
| words[].due | 文本 | 下次复习日期 |
| words[].added | 文本 | 加入日期 |
| logs | 对象 | 以日期为键的学习日志 |
| logs[日期].read | 数组 | 阅读记录（标题、分钟、笔记） |
| logs[日期].newW | 数 | 当日新增单词数 |
| logs[日期].rev | 数 | 当日复习次数 |
| logs[日期].sh | 数 | 当日跟读句数（可选字段） |
| logs[日期].dc | 数 | 当日听写句数（可选字段） |
| logs[日期].done | 布尔 | 当日是否已打卡 |
| lessons | 对象 | 以课文标识为键，值为读完日期 |
| set.voice | 文本 | 备用发音语言，默认欧洲葡语 |
| set.goalW | 数 | 每日新词目标，默认 **5** |
| set.goalMin | 数 | 每日阅读目标分钟，默认 **15** |
| set.revBatch | 数 | 每轮复习上限，默认 30 |
| set.weekGoal | 数 | 每周达标天数，默认 5 |
| set.v3 | 数 | 数据结构版本标记，用于一次性迁移 |
| seq | 数 | 标识分配游标 |

### 8.3 日期与跨天处理

| 规则 | 说明 |
|---|---|
| 日期格式 | `YYYY-MM-DD` |
| 本地化 | 按设备本地时区计算，不使用 UTC 日期，避免跨时区错日 |
| 跨天刷新 | 页面从后台恢复可见时重渲染当前标签页 |
| 迁移 | 检测到旧版本标记时，统一把备用发音设为欧洲葡语并写入版本标记 |

### 8.4 备份与恢复

| 项 | 规则 |
|---|---|
| 导出 | 生成带日期文件名的 JSON 文件，通过浏览器下载 |
| 导入 | 读取本地文件，校验必须含 words 与 logs 字段，格式不符则报错不写入 |
| 导入前提示 | 明确告知会覆盖当前数据并二次确认 |
| 导入后 | 重载页面使全部视图刷新 |
| 备份时机建议 | 每周导出一次并存入 iCloud 或文件 App；换设备前必须导出 |

## 10. 学习内容设计规范

### 10.1 课文结构

| 字段 | 类型 | 约束 |
|---|---|---|
| id | 文本 | 唯一，命名规则为 L 加两位序号 |
| level | 文本 | 难度级别，A1 或 A2 |
| min | 数 | 预计分钟数 |
| title | 文本 | 葡语标题 |
| zh | 文本 | 中文标题 |
| text | 文本 | 正文，段落以换行分隔 |
| trans | 文本 | 中文翻译，与正文段落数对应 |
| note | 文本 | 中文语法点讲解 |
| words | 二维数组 | 每行为葡语、释义、例句三项 |
| qs | 二维数组 | 每行为问题、参考答案两项 |
| sents | 数组 | 由构建脚本生成，含文本、段落序号、音频相对路径 |
| wa | 数组 | 由构建脚本生成，与 words 一一对应的音频路径 |

### 10.2 难度与篇幅

| 级别 | 目标 | 句长 | 课文时长 | 词汇量 |
|---|---|---|---|---|
| A1 | 入门，建立语感 | 短句为主 | 5 分钟左右 | 每篇 10 至 12 词 |
| A2 | 覆盖日常与校园场景 | 中等长度，含从句 | 6 至 8 分钟 | 每篇 12 词 |

### 10.3 主题与情境

| 层次 | 主题 |
|---|---|
| 校园生活 | 自我介绍、校园、食堂、作息、课程 |
| 澳门本地 | 美食、市场、市中心、交通、天气 |
| 未来规划 | 交换、住宿、城市、目标 |
| 对话形式 | 购物、问路、社交（每行对话自动分配两个声音） |

内容全部原创，不引用教材或报纸原文，避免版权风险。语法点基于欧洲葡语规范，与课堂讲法冲突时以教师为准。

### 10.4 欧葡规范要点（写作约束）

| 规范点 | 要求 |
|---|---|
| 反身代词 | 置于动词后并连字符连接，如 chamar-se |
| 冠词与缩写 | 介词与冠词缩合，如 em 加 a 得 na |
| 过去时重音 | 完成过去时的 nós 形式在欧葡需加重音（comprámos 对 compramos），用于与现在时区分；巴葡不加 |
| 动词与介词 | gostar 后必须接 de，adorar 直接接宾语 |
| 被动 se | 构成被动含义，如 comem-se |
| 数字与日期 | 日期写数字式 DD/MM/AAAA，日与月不补零（3/5/2026）；月份与星期名小写；小数用逗号，不用小数点；0 至 999 逐位读，1000 以上按千分组读 |
| 天气表达 | 用 estar 与 haver，无人称动词 chover 与 nevar |

## 14. 学习闭环设计（2026-10-07 新增）

> 本章回答一个问题：**她凭什么在第 21 天之后还在用。**
> 判断一个功能值不值得做，先过这一关。

### 14.1 核心判断：最大的风险是积压，不是功能不够

间隔复习类 App 最常见的弃用原因是**待复习的词越积越多**。典型场景：期中考试忙了三天没打开，回来一看待复习 80 个，直接就不想打开了。

原设计把到期的词一次性塞进队列，没有上限，等于把「欠账」全部摊在首屏。这是设计缺陷，不是使用者的意志问题。

| 层级 | 规则 | 参数 |
|---|---|---|
| 单轮上限 | 每轮最多取 N 个到期的词 | 默认 30，可设置 |
| 轮次结束 | 提示「再来一组 / 今天到此为止」，两个选项都给 | 无强制 |
| 积压阈值 | 待复习超过 M 个视为积压 | M = 50 |
| 积压期间 | 今日页提示「今天先复习，不加新词」，打卡条件从「新词达标」改为「完成一轮复习」 | 无 |
| 默认目标 | 每天 5 个新词、阅读 15 分钟 | 可上调 |

**为什么默认目标要下调**：每天 10 词、20 分钟，一年就是 3650 个词。对课业不轻的大一学生，这个量很难天天坚持。**目标定低一点、能天天完成，比定高了经常完不成更能坚持下去。**

### 14.2 已确认的现有行为（不要重复实现，也不要误改）

这两条是代码现状，coder 需在改动时保持：

| 行为 | 机制 | 推论 |
|---|---|---|
| 没记住的词当轮一定还会出现 | 点「没记住」使 `box` 归零、`due` 设为今天，并放回队尾 | 只要队列里还有没记住的词，**队列不可能提前清空**。因此不需要额外实现「清空后重排错词」 |
| 熟练度 6 的词不会消失 | 对应 30 天间隔 | 该词每 30 天仍会出现一次 |

### 14.3 日常闭环的三个环节

| 环节 | 现状 | 改进 | 优先级 |
|---|---|---|---|
| **次日打开** | 四个进度条，展示「还差多少」 | 首屏改为「下一步」卡片，一句话加一个按钮 | 高 |
| **当场练习** | 复习页安静换卡；听写判词但只在课文页深处 | 复习给即时反馈与轮次小结；快速听独立入口 | 高 |
| **长期可见** | 月历与五项数字 | 错词本（`lapse >= 3`）、周目标兜底 | 中 |

**次日打开**的三种状态按固定顺序判断：有到期词 → 复习；无到期词且有未读完课文 → 继续读；两项都完成 → 打卡。

**当场练习**的三点反馈（成本很低，价值很高）：

| 反馈 | 内容 | 作用 |
|---|---|---|
| 间隔可见 | 点「记住了」后提示约 0.8 秒「下次：N 天后」 | 让间隔算法的结果可见，用户能理解盒子在涨 |
| 轮次小结 | 本轮共几个词、记住几个、待巩固几个 | 一天的成果可见 |
| 单词轮换 | 一轮结束后的「再来一组」 | 30 个一轮比 80 个一次性更可完成 |

### 14.4 快速听写的句子来源

独立听写从**她读过的课文**里随机抽 5 句，条件是该句有 `sents[].a` 音频。

| 为什么 | 说明 |
|---|---|
| 有现成音频 | 不需要为听写单独合成，零额外额度 |
| 不超水平 | 抽自她读过的课文，用词都在她当前水平内 |
| 不加重负担 | 复习完成页和今日页都能进入，5 句约 3 分钟 |
| 边界清晰 | 没读过任何课文时不显示入口 |

### 14.5 明确不做的功能

| 功能 | 理由 |
|---|---|
| 音频波形可视化 | iOS 上性能差收益低，逐句播放已足够 |
| 复杂统计图表 | 五个数字已够，对大一学生无指导意义 |
| 社交与排行榜 | 单人使用，加了就是空的 |
| 离线打包整站 | Service Worker 已覆盖，体积会失控 |
| 补签卡 | 周目标已提供同类兜底，且实现复杂得多 |
